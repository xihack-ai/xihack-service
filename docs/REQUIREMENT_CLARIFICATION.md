# 创建职位前的需求澄清

2026-10-04 修复：原有 `generate_spec → risk_review` 将模糊需求抛为 `NEEDS_CLARIFICATION` 异常，前端只展示错误字符串，经理没有回答入口。

新版前端先调用 `POST /requirements/clarify`。该接口不创建职位、标准或评估；返回 `SAFE / NEEDS_CLARIFICATION / BLOCKED`，包含问题、选项和原因。用人经理逐题回答，HR 可代填；已回答内容随下一轮请求再次审核。初次 SAFE 仍由需求澄清节点检查职责歧义；后续轮次结合完整问答进行语义审核，不再独立生成一轮重复问题。

```json
{
  "requirement": "希望找一名比较 senior 的后端，能独立负责 AI 系统",
  "answers": [
    {"question": "独立负责哪些职责？", "answer": "负责技术方案、上线及故障处理，不要求人员管理"}
  ]
}
```

SAFE 后前端调用 `/jobs`，原始需求和 `clarification_answers` 一起提交。后端重新审核回答，不信任前端 SAFE 状态；将原始需求与经理问答保存为可核对的需求来源，再生成草稿并停在 `spec_confirmation`，不会提前评估候选人。后续生成审核若再次提出问题，以结构化 `questions` 返回，前端继续展示回答表单，不把问题压成顶部警告。

修改原始招聘意图或新建职位会清除旧问答；候选人文本保持原输入，不插入模拟简历。BLOCKED 提示编辑原需求；模型错误仍作为任务错误。初始问答尚未创建职位时保留在当前页面内存，刷新会丢失；发布草稿后问答保存在职位需求文本中。既有确认后逐题澄清反馈与人工审批流程继续保留。

验证：`tests/test_requirement_answers.py` 新增 6 个用例，覆盖无需建职位的追问、SAFE 后仍有问题、回答到草稿暂停、敏感回答复检、继续追问及模型任务错误。全量回归 221 passed、18 skipped；使用测试模型替身，不宣称真实模型准确率。

## 指定公司名单重复追问修复

原因：需求审核保留了问答，但生成模型可能将已指定公司名单缩回“大厂经验”；标准审核还只接收文本，丢失 NICE_TO_HAVE / MUST_HAVE 类型，于是重新问范围和优先级。

修复：生成 Prompt 要求每条标准自包含经理已给的完整公司范围；标准审核传入标准类型。已给具体名单及必须/优先类型时，不额外要求公司市值、营收或规模。原需求审核已通过、生成草稿却又出现歧义时，系统先重生成一次以补齐遗漏；仍失败返回模型任务错误，保留问答，不让经理重复回答。敏感筛选条件继续拦截。

真实个人 DeepSeek API 本地复测模拟需求及经理回答“腾讯 阿里 字节 美团”“优先考虑项，非必须”：需求审核 SAFE，生成 `NICE_TO_HAVE: 曾在腾讯、阿里、字节或美团工作`，标准复检通过。该次本地复测不创建数据库职位。前端示例按问题类别变化，公司问题使用名单示例。新增两项回归覆盖丢名单后的自动修复、公司范围与类型保留到确认、连续生成失败不冒充经理需澄清。全量 223 passed、18 skipped；静态构建通过。公网已发布 `release-20261004-company`，服务器另以独立模拟任务验证真实数据库写入、确认和候选人评估，记录见服务器部署文档。
