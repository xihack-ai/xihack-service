# 反馈审核与经理澄清

审核结果独立保留 SAFE、NEEDS_CLARIFICATION、BLOCKED。模糊反馈不是歧视，不因模糊而拦截。

明确按候选人年龄、性别、婚育、民族、宗教、种族、残障或外貌筛选时拦截。产品业务背景不因出现相关词就拦截；混合反馈须编辑原反馈后重新审核，不自动替换经理意图。

大厂、公司、学历、专业、学校背景不因关键词被禁止；定义或岗位必要性不明时向用人经理追问。学校个人好恶须澄清岗位原因。主动性、冲劲、快节奏等模糊要求同样走澄清。这是产品规则，不代表法律合规结论。

## 接口

POST `/calibrations/{job_id}/feedback` 开始新反馈；返回 `feedback_id`、`feedback_review`（状态、原因、相关输入、最多三条问题和选项）与 `feedback_thread`。

POST `/calibrations/{job_id}/feedback/answer` 继续原反馈：

```json
{"feedback_id":"当前返回的ID","base_spec_version":1,"answers":["逐题回答，可自由输入"],"created_by":"manager"}
```

用人经理回答，HR可代填。回答数量必须匹配问题，空白、过期版本、旧反馈ID和重复回答被拒绝。原反馈与历次问答保存在同一 checkpoint 会话；每轮反馈和 FEEDBACK_CLARIFIED 审计记录存入现有数据库表，不新增表、不覆盖正式版本。

回答重新审核，可能继续澄清、拦截、无变更或产生待审批提议。只有批准提议才发布新版并重评。敏感回答或人工编辑仍不能绕过审核。模型错误返回任务错误，不冒充拦截或无证据。

前端提供逐题选项与自由填写、问答历史、审核范围说明、拦截理由和原反馈编辑；删除通用能力替换按钮。历史任务缺少新增字段仍可读取；旧记录未保存原反馈时不虚构。
